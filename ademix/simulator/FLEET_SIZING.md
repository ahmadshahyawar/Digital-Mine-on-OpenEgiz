# A8 fleet-sizing evidence

This is a deterministic planning experiment generated by the existing Ademix
engine. It is synthetic model evidence, not measured mine performance and not a
claim that the selected values are optimal for a real site.

Regenerate the versioned fixture from the repository root:

```bash
python ademix/simulator/fleet_sizing.py --write
```

Each case creates a fresh fixed-dispatch engine with seed 42, runs four simulated
hours of baseline warm-up, excludes one transition hour, and measures the next
eight hours in 20-second event-driven steps. Only fleet size changes between the
2–6 truck cases. The six live truck twins and runtime topology are unchanged.

## Result

| Condition | 2 trucks t/h | 3 trucks t/h | 4 trucks t/h | 5 trucks t/h | 6 trucks t/h | Model recommendation |
|---|---:|---:|---:|---:|---:|---|
| Normal operations | 415.1 | 623.9 | 770.0 | 770.0 | 770.0 | 4; excavator limit reached |
| HT-01 breakdown | 210.2 | 414.9 | 624.3 | 770.0 | 770.0 | 5 total; one is unavailable |
| Road restriction | 221.3 | 327.3 | 435.2 | 540.1 | 645.3 | At least 6; no plateau in tested range |
| Crusher −45% | 415.0 | 495.0 | 495.0 | 495.0 | 495.0 | 3; crusher limit reached |

In normal operations, the fourth truck raises output to the single excavator's
770 t/h limit. A fifth truck adds no production but raises operating truck-hours
from 5.19 to 6.49 h per 1,000 t and increases the average face queue from 0.27 to
1.27 trucks. Six trucks raise those values to 7.79 h per 1,000 t and 2.27 trucks.
This is why fewer cycling trucks work in baseline and more trucks help under a
road restriction, where the tested range never reaches a plateau.

The complete values, units, start-state hashes, queues, waits, utilization,
trips, mass-balance error and recommendation rule are in
`../data/evidence/fleet_sizing.json`.
