# Final submission acceptance gates

These are mandatory results for the exact release candidate. A passing unit
test, build or earlier branch does not substitute for evidence from the final
combined commit. Do not merge official `main` until every gate is accepted.

## 1. One understandable journey

Required journey: baseline → disruption → physical consequence → Smart response
→ numerical evidence → reset.

Pass when a new viewer completes the journey using real controls and returned
twin state, explains the recommended action, and reset restores fixed/baseline
without stale state. Professor + Claude own presentation; Ahmad + Codex own live
scenario/reset verification.

## 2. Complete agreement

Pass when visible activity, all 11 twins, Decision charts, A8/A9 fixtures,
README, SUBMISSION and final PDF use the same scenarios, units, assumptions,
values and limitations. Every number must point to live state or a versioned
fixture; saved evidence must not be labelled live.

## 3. Truthful failure handling

Pass when stale or unavailable Ditto data cannot show a LIVE/fresh label, missing
fields render unavailable rather than zero/success, failed controls do not imply
acknowledgement, and recovery resumes advancing twin timestamps before the UI
returns to live status.

## 4. Usable software-rendered mine

Pass when the exact final frontend is measured without GPU acceleration in
Balanced mode at the documented viewport. Record first usable frame, frame-rate
range and interaction behavior in baseline and the busiest scenario with the
Decision and inspection panels open. No missing asset, WebGL error, prolonged
freeze or unusable camera/control state is accepted.

## 5. Reproducible final release

Pass when a clean Ubuntu 24.04 AMD64 host checks out the exact remote official
`main` SHA and follows README commands without undocumented intervention. Require
healthy startup, repeated smoke checks, 11 twins/complete field-unit contract,
advancing simulation/production, the full fixed/smart scenario matrix, no
recurring Ditto 503 and a successful stack restart. Archive workflow/log evidence.

## 6. Evidence-based rubric review

Pass when each official rubric criterion lists the exact runtime screen, source,
fixture, test, document or presentation page supporting its highest claimed
level. Any unsupported claim is removed or corrected. The weakest demonstrable
criterion is fixed before submission; no score is self-awarded without evidence.

## Ownership and order

- Professor + Claude: finish B/C interface work, visibly consume
  `ademix.decision-explanation.v1`, and provide human visual acceptance.
- Ahmad + Codex: independent calculations, long-run/recovery checks, contract
  verification, integration, Ubuntu evidence and release audit.
- Integrator: reconcile all surfaces, freeze one SHA, execute gates 1–6, then and
  only then merge/push official `main`.
